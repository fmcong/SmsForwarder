# 2026-07-18

## 代码检查 + 修复 + GitHub Workflow 排错

### Workflow 失败原因与修复
- 根因1：APK 输出路径写反。模块为 `:app`，正确路径是 `app/build/outputs/apk/release/`，但 `Weekly_Build.yml` 与 `Release.yml` 都写成 `build/app/outputs/apk/release`，导致 `output-metadata.json` 与 APK 找不到而失败。已修正。
- 根因2：`Release.yml` 含非法配置 `pull_request: tags:`（pull_request 不支持 tags），会导致整个 workflow 校验失败无法运行。已移除。
- 根因3：`Release.yml` 用已归档的 `actions/create-release@v1` + 已损坏的 `alexellis/upload-assets@0.2.2`，且缺 `permissions: contents: write`（创建 release 会 403）。已替换为 `softprops/action-gh-release@v2` 并加权限。
- 其它：Release 原先未把 keystore 复制到 `app/`（与 Weekly_Build 不一致），已补复制步骤；Weekly_Build 清理旧运行步骤加 `continue-on-error`。
- 注意：`actions/checkout@v5`/`upload-artifact@v5` 均已发布（非失败原因），保留。

### 代码修复
- `SM4Crypt.doSM4`：异常时不再 `printStackTrace`+返回空数组（调用方误判成功），改为直接抛异常；`ActionWorker` 已 try/catch 包裹，安全。
- 凭据脱敏：`WeworkAgentUtils`(corpsecret+代理密码)、`WebhookUtils`/`TelegramUtils`/`DingtalkInnerRobotUtils`(代理密码) 日志改为 `******`。
- `App.kt` `SimInfoList` 改用 `ConcurrentHashMap`（广播/WorkManager 并发读写安全）。
- `EmailUtils` 三处 keystore `FileInputStream` 用 `use{}` 关闭（含 283 行重复新建 FileInputStream 的泄漏）。

### 未改动（已知限制，需权衡）
- 全局 `Authenticator.setDefault`（SOCKS 代理鉴权）：OkHttp 无 per-client SOCKS 鉴权 API，改动会破坏 SOCKS，保留。
